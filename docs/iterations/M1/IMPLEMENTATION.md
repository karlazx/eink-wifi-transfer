# M1 实现说明

用户于 2026-10-20 确认首版范围，并明确禁用 `sdd-governance`；本迭代按项目 AGENTS.md 开发与验证，不再使用该技能门禁。用户另明确无需大文件测试，已取消 100 MiB 验收要求。

## 结构

- `MainActivity.java`：原生黑白界面、Android 存储权限、Wi-Fi 地址、二维码、文件列表、服务与屏幕唤醒的生命周期。
- `TransferServer.java`：与 Android 解耦的 Java HTTP/1.1 服务，可在主机运行同一实现的集成测试。
- `assets/web/`：独立编写的响应式网页，无前端依赖；多选串行队列、进度、取消、列表、下载与确认删除。
- `scripts/build.py`：JDK 17 与 Android SDK 34 直接构建，不依赖 Gradle。ZXing 3.5.3 固定版本并校验哈希，仅用于生成二维码。

## 接口与文件策略

| 方法与路径 | 行为 |
| --- | --- |
| `GET /`、`/app.js`、`/style.css` | 内置网页 |
| `GET /api/files` | 接收目录中已完成普通文件的名称、字节数 |
| `PUT /api/file?name=<UTF-8 URL 编码名称>` | 请求体为原始文件字节，要求 Content-Length；成功 201 |
| `GET /api/file?name=…` | 作为附件下载，不执行内容 |
| `DELETE /api/file?name=…` | 仅删除指定接收文件；网页先确认 |

只在 Wi-Fi 的 IPv4 地址监听 8080；用户手动停止、确认退出、切换应用或 Wi-Fi 地址变更时关闭原连接。重新进入可重新启动。服务占用端口则显示错误，不抢占原厂应用。

接收路径为共享存储 `EInkTransfer`。上传使用 32 KiB 缓冲，写入内部 `.eink-partials` 子目录，完整接收并同步后才提交正式文件；中断时删除临时文件，重启清理本应用遗留临时文件。用锁和名称保留集合保护本服务的并发重名，不静默覆盖。迟到取消不能删除已完成文件，网页通过刷新列表确认结果。

不按扩展名、MIME 或内容过滤；合法无扩展名及零字节文件可传输。文件名 UTF-8 长度最多 240 字节，拒绝路径、控制字符和内部临时目录名称。单文件防护上限 2 GiB；这是实现阈值，未实测此大小，不承诺大文件性能。最大 4 个活动工作线程，8 个排队连接；空闲连接 30 秒超时。

无认证，供可信局域网使用。限制 Host 与跨站 Origin，不开放 CORS；文件名用 textContent 展示，下载设置 attachment、nosniff，页面配置 CSP。服务不读取其他目录，不依赖系统签名或原厂书库。

## 兼容与边界

最低 Android 8.0 / API 26，目标 API 28，以 Android 8.1 / API 27 实机验证。新版 Android 的共享存储权限模型尚未适配和验证，不作为首版兼容承诺。保留后续替换存储层与增加配对方式的空间；首版无云服务、后台常驻、断点续传或自动安装。
